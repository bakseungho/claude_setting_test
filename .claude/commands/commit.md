# 커밋 자동화

변경 사항을 분석하여 커밋 메시지를 생성하고 사용자 확인 후 커밋합니다.

## 1단계: 변경 사항 확인

```bash
git status
git diff --staged
git diff
```

스테이징되지 않은 파일이 있으면 전체 변경 파일을 `git add -A`로 스테이징합니다.

## 2단계: 커밋 메시지 생성

변경 내용을 분석하여 Conventional Commits 형식으로 메시지를 작성합니다.

형식: `<type>: <subject>`

| type | 사용 시점 |
|------|----------|
| feat | 새 기능 추가 |
| fix | 버그 수정 |
| refactor | 리팩토링 |
| docs | 문서 변경 |
| chore | 설정, 패키지 등 기타 |
| style | 코드 스타일 변경 |
| test | 테스트 추가/수정 |

## 3단계: 사용자 확인

생성된 커밋 메시지를 보여주고 확인을 요청합니다:

```
📝 커밋 메시지:
  <type>: <생성된 메시지>

진행할까요? (y/n)
```

## 4단계: 커밋 실행

사용자가 **y**를 입력하면:

```bash
git add -A
git commit -m "<생성된 메시지>"
```

**n**을 입력하면 메시지를 수정하거나 취소합니다.

## 주의사항

- `.env`, `*.key`, `*.pem` 파일은 절대 스테이징하지 않습니다
- 변경 사항이 없으면 커밋하지 않고 안내합니다
