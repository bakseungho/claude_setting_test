# 커밋 자동화

## 1단계: 스테이징 상태 확인

```bash
git status
```

### 스테이징된 파일이 있는 경우
스테이징된 파일 목록을 보여주고 확인합니다:
```
📋 스테이징된 파일:
  - src/user.service.ts
  - src/user.controller.ts
  (총 N개)

이 파일들만 커밋할까요? (y/n)
```
→ y: 스테이징된 파일만 커밋 진행
→ n: 중단

### 스테이징된 파일이 없는 경우
변경된 전체 파일 목록을 보여주고 선택지를 제시합니다:
```
📋 변경된 파일 (N개):
  1. src/user.service.ts
  2. src/user.controller.ts
  3. src/auth.service.ts
  ...

전체 커밋할까요, 아니면 일부 파일만 선택하시겠어요?
  a) 전체 커밋
  b) 파일 직접 선택 (예: 1,2,3)
```
→ a 선택: `git add -A` 후 커밋 진행
→ b 선택: 번호 입력받아 해당 파일만 `git add` 후 커밋 진행

## 2단계: 커밋 메시지 생성

변경 내용을 분석하여 아래 형식으로 메시지를 작성합니다.

### 커밋 타입

| 타입 | 사용 시점 |
|------|----------|
| feat | 새 기능 추가 |
| fix | 버그 수정 |
| refactor | 기능 변경 없는 코드 개선 |
| docs | 문서 변경 |
| chore | 설정, 패키지, 빌드 등 기타 |
| style | 코드 스타일, 포맷 변경 |
| test | 테스트 추가/수정 |
| perf | 성능 개선 |

### 커밋 메시지 형식

```
<타입>: <한 줄 요약>
- <변경 항목 1>
- <변경 항목 2>
- <변경 항목 3>
```

규칙:
- 제목과 본문 사이 공백 줄 없음
- 본문은 `-` 불릿 포인트로 핵심만 간결하게
- 제목은 50자 이내, 현재형 동사로 작성
- `.env`, `*.key`, `*.pem` 파일은 절대 포함하지 않음

### 예시

```
feat: 사용자 인증 기능 추가
- JWT 토큰 발급 및 검증 로직 구현
- 로그인/로그아웃 API 엔드포인트 추가
- 인증 미들웨어 적용
```

## 3단계: 사용자 확인

```
📝 커밋 메시지:

feat: 사용자 인증 기능 추가
- JWT 토큰 발급 및 검증 로직 구현
- 로그인/로그아웃 API 엔드포인트 추가
- 인증 미들웨어 적용

진행할까요? (y/n/e)
  y) 커밋 실행
  n) 취소
  e) 메시지 직접 수정
```

## 4단계: 커밋 실행

y 선택 시:
```bash
git commit -m "<타입>: <요약>
- <항목1>
- <항목2>"
```

변경 사항이 없으면 커밋하지 않고 안내합니다.
